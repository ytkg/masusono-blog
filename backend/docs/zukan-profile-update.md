# 増その図鑑プロフィール更新手順

記事が増えたときに、`増その図鑑` のプロフィール文を再更新するための手順です。
完全に同じ文章を再現することは目的にせず、同じ判断軸で「同じ人物像に見える」状態を目指します。

## 更新対象

- プロフィールデータ: `app/frontend/features/apps/zukan/zukanData.js`
- 表示コンポーネント: `app/frontend/features/apps/zukan/ZukanApp.jsx`
- 人物画像: `app/frontend/features/apps/zukan/assets/`

通常のプロフィール更新では `zukanData.js` だけを変更します。
表示構造やIDを変えない限り、テストの期待値はプロフィール文ごとに修正しない方針です。

## 基本方針

- 記事内容そのものは書かない
- 記事群から見える性格、価値観、癖、関係性の扱い方を書く
- 事実ベースにするが、文章は少しユーモア寄りにする
- 「ですます」口調は使わない
- 内輪ノリは入れてよいが、初見でも人物像が浮かぶ範囲に留める
- 断定しすぎず、「そういう傾向がある人」として書く
- 悪口や外見いじり、センシティブな推測は入れない

## 入力として集めるもの

各メンバーごとに、最近の記事から次の情報だけを抜き出します。

- 取得元は `https://masusono.com/feed.xml` を使う
- `dc:creator` でメンバーを判別する
- `title`、`pubDate`、`description`、`link` を材料として読む

- 繰り返し出てくる関心事
- 人との距離感、友人や家族への向き合い方
- 迷ったとき、楽しいとき、疲れたときの反応
- 文章の温度感
- 行動の癖
- 読後に残る印象

記事タイトル、旅行先、イベント名、具体的なエピソード名はプロフィール本文に直接入れません。
それらは人物像を作るための根拠としてだけ使います。

## 作業手順

1. `https://masusono.com/feed.xml` から新しい記事を確認する
2. `dc:creator` を見て各記事をメンバー別に分ける
3. メンバーごとに、人物像の材料を箇条書きで集める
4. 古いプロフィールと新しい材料を見比べる
5. 変わっていない核は残し、増えた傾向だけを足す
6. キャッチコピーを1行で更新する
7. プロフィール文を4文前後で更新する
8. 実画面で余白、改行、文章量を確認する
9. テストとlintを実行する

## feed.xml の見方

`feed.xml` では、各記事が `<item>` として入っています。

- `<dc:creator>`: 誰の記事か
- `<title>`: 記事タイトル
- `<pubDate>`: 公開日時
- `<description>`: 本文の要約ではなく、記事内容の本文断片
- `<link>`: 元記事URL

`description` はHTMLを含むので、そのままプロフィール文へ転記しません。
人物像の材料を拾うために読み、本文には固有イベントや記事タイトルを直接入れない方針は維持します。

## キャッチコピーの書き方

キャッチコピーは、名前の上に出る短い人物ラベルです。

- 15〜25文字程度
- 名詞句で終える
- 人物の核が一目で伝わる
- 少しだけ変な言い回しにしてもよい

例:

- 生活を検証する考察エンジニア
- 余白とごきげんの回復担当
- 考えすぎと勢いの共存タイプ

## プロフィール文の書き方

プロフィール文は、記事を読んでいない人にも人物像が浮かぶ説明にします。

- 4文前後
- 180〜240文字程度
- 前半は事実から見える性質
- 中盤は人との関係、感情、行動の癖
- 最後の1文で少しユーモアを足す
- 記事のあらすじや固有イベントは書かない

構成例:

```text
○○を大事にしている人。△△な場面では□□しがちで、文章からは◇◇が見える。□□だけではなく、▽▽にもちゃんと心が動くところが面白い。たぶん××を渡すと、最終的に○○になって返ってくる。
```

## AIに依頼するときのプロンプト

プロフィール更新をAIに依頼するときは、次の形で渡します。

```text
「増その図鑑」のプロフィールを更新したい。

目的:
- 記事が増えた分を反映して、各人物のプロフィールを更新する
- 記事内容の要約ではなく、記事群から見える人物像を書く
- 初見でもその人の性格、価値観、癖が浮かぶようにする

文体:
- 日本語
- 「ですます」口調は禁止
- 事実ベース
- 少しユーモアあり
- 内輪ノリ寄りだが、初見でも意味が通る範囲
- 悪口、外見いじり、センシティブな推測は禁止

出力:
- 各人物ごとに `title` と `bio` を出す
- `title` は15〜25文字程度の名詞句
- `bio` は4文前後、180〜240文字程度
- 記事タイトル、イベント名、具体的な記事内容は本文に直接書かない
- その人を説明する文章にする

既存プロフィール:
ここに `app/frontend/features/apps/zukan/zukanData.js` の現在の内容を貼る

追加で読んだ記事メモ:
ここに人物ごとの観察メモを貼る
```

## レビュー観点

更新後は、次の観点で見直します。

- 記事の説明になっていないか
- どの人物にも使える薄い表現になっていないか
- 根拠のない決めつけがないか
- ユーモアが人物理解の邪魔をしていないか
- 口調に「ですます」が混ざっていないか
- 文章量がカード内で重すぎないか
- キャッチコピー、名前、プロフィール文の余白が崩れていないか
