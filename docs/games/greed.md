# 強欲は身を滅ぼす？ 初期バランス検証

2026-10-21の訂正仕様を反映。自分が払う場合は全員分を減算する元のルールを維持し、入手商品には自腹分も含める。価格・確率式・CPU範囲の変更なし。

自分の商品代x、CPUの商品代a・b、支払確率p=x²/(x²+a²+b²)に対し、期待収支は (1−p)×x−p×(x+a+b)。スコアはゲーム上の収支であり、入手商品総額と支払累計の差額ではない。

## 読み取り

代表条件では最低100円より1,000〜2,000円の期待収支が高く、最低額だけが有利な設計ではない。一方、6,000〜10,000円は期待収支が負で、高額購入を繰り返すと大幅なマイナスになりやすい。高額でも3ラウンドすべて奢ってもらえば大きい記録を狙えるため、期待値重視と最高記録狙いで判断が分かれる。

例：CPU2,000円・6,000円、自分10,000円では1回の支払確率71.43%、3回とも奢ってもらう確率約2.33%。この分散と不利さは初期仕様によるもの。自動バランス調整・記録リセットは設けない。確率式・価格・CPU範囲を変更する場合はオーナー判断が必要。

確率と手合わせのテストでは代表金額4組×自分の手3種×6,000ラウンドを検証する。最終支払者を先に抽選し、各手合わせはその人が勝ち残る合法な組合せから生成する。あいこや2人決戦では支払者を抽選し直さない。

## 試遊

2026-10-20、専用環境をブラウザで操作し、乱数を固定せず3ラウンド完走した。
1ラウンド目は2,700円を選び、CPU2が奢って+2,700円。
2ラウンド目は8,000円を選び（奢ってもらえる表示43.04%）、3人あいこ→自分とCPU2の決戦→2人あいこ→自分が勝ち残り、全員分16,480円を減算。
3ラウンド目は100円でCPU2に奢ってもらい、最終−13,680円を初回自己ベストとして表示した。
CPUの買い直し、自分のカゴ初期化、手の選び直し、支払額と合計の一致を確認した。

試遊では中額・高額・少額の結果の振れを確認できたが、長期的な遊びやすさはこの1ゲームだけで断定しない。初版のルール変更は提案せず、公開後の試遊結果に応じてオーナーが判断する。

## 最終結果の振り返り

1ゲームの確定結果をメモリに3ラウンド分保持し、終了時に支払者にかかわらず全ラウンドの自分の商品を合算する。CPUの商品は入手商品に含めない。
自分が奢ったラウンドは全員分を支出として集計し、購入者ごとの商品・数量・小計を折りたたみで確認できる。
通常の会計レシートは従来どおり購入者名なし。履歴の商品価格・数量は決着時にコピーし、再挑戦・閉じる・再読み込みで破棄する。
「CPUに奢ってもらった自分の商品代 − 自分の支払い合計」が最終スコアになる。入手商品には自腹分も入るため「入手総額−支払累計」とスコアは一致しない。確率・点数・自己ベスト保存は変更せず、既存記録の移行・削除もしない。
画面では「今回のスコア」「合計スコア」と表記し、入手商品と実支払額から区別する。
最終スコアが−10,000円以下の場合に限り、振り返りの後・再挑戦の前に「今日は納豆ご飯だ。」を表示する。途中結果では表示しない。

例：自分2,000円、CPU3,000円・5,000円なら、奢ってもらうと+2,000円、自分が奢ると−10,000円。
自分の商品が毎回2,000円でCPU→自分→CPUが払った場合、入手6,000円分・支出10,000円・スコア−6,000円になる。
